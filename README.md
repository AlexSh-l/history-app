# Тестовое задание

Добро пожаловать в репозиторий тестового задания! Вам предстоит разработать концепт фронтенд-части информационной платформы, посвященной истории.

**Цель:** Оценить ваши навыки работы с современным стеком Next.js, управление состоянием, реализацию мультиязычности и общую чистоту кода.

---

## Технологический стек

Проект должен быть выполнен со следующим набором технологий:

- **Фреймворк:** Next.js (App Router) + TypeScript
- **Менеджер состояния:** Zustand
- **Получение данных:** TanStack Query (React Query)
- **Локализация:** `next-intl` или `react-i18next` (с интеграцией в роутинг App Router)
- **Стилизация:** На ваш выбор (Tailwind CSS, SCSS, CSS Modules)

---

## Список задач

### 1. Инициализация и настройка проекта

- Настроить проект Next.js с использованием App Router и TypeScript.
- Настроить локализацию для трех языков: **белорусский (`be`)**, **русский (`ru`)**, **английский (`en`)**.
- **Важно:** Переключение языка должно корректно менять локаль в URL (например: `/be/article/minsk`). По умолчанию должна использоваться локаль `be`.
- **Правила работы с Git:**
  1. Создайте **собственный публичный репозиторий** на GitHub/GitLab (или сделайте Fork этого репозитория в свой аккаунт).
  2. Разработку необходимо вести в отдельной ветке. Назовите ветку по шаблону: `feature/your-name-wikipedia` (например: `feature/ivan-ivanov-wikipedia`).
  3. Пишите понятные, атомарные коммиты (желательно по конвенции Conventional Commits, например: `feat: add live search with debounce`).
  4. По окончании работы создайте Pull Request из вашей ветки в ветку `main` **вашего** репозитория и отправьте ссылку на PR проверяющему ментору.

### 2. UI (Дизайн)

- Для выполнения тестового задания используйте структуру, компоненты и визуальный стиль из дизайн-макета: [Frontend-developer (Figma)](https://www.figma.com/design/xiLGZdMQ1zb6h9wOMXgTqP/Frontend-developer?node-id=0-1&p=f)

### 3. Главная страница и Живой поиск (Live Search)

- В шапке сайта (Header) реализовать поисковую строку.
- Поиск должен быть «живым» (фильтрация статей на лету по названию).
- **Обязательное условие:** Использовать **debounce** (задержку ввода 300ms), чтобы оптимизировать количество запросов.
- Результаты поиска необходимо выводить в выпадающем списке под строкой ввода.

### 4. Страница «Все статьи» (Каталог)

- Отобразить сетку или список всех доступных статей.
- Реализовать фильтрацию по двум параметрам:
  1. **Категория** (История, Города, Личности, Культура).
  2. **Регион/Область** (Минск, Брест, Гродно, Витебск, Могилев, Гомель, или "Вся Беларусь").

### 5. Динамическая страница статьи (`/article/[slug]`)

- Реализовать роутинг для отображения конкретной статьи по её уникальному параметру `slug`.
- Данные должны запрашиваться через **TanStack Query** (имитируя запрос к API с использованием файла `articles.json`).
- Обязательно обработать и визуально отобразить 3 состояния: **Loading** (скелетон или лоадер), **Error** (сообщение об ошибке) и **Success** (контент).

### 6. Избранное (Управление состоянием в Zustand)

- На странице статьи добавить кнопку «В закладки» / «Удалить из закладок».
- Реализовать отдельный экран (или блок на странице) со списком сохраненных статей.
- Состояние закладок должно управляться через **Zustand** и синхронизироваться с **LocalStorage**, чтобы данные сохранялись при перезагрузке страницы.

## Критерии оценки

- **Архитектура:** Организация компонентов, кастомных хуков и структура папок в App Router.
- **TypeScript:** Правильная типизация без использования `any`.
- **Локализация:** Корректная обработка смены языков в контенте, метатегах и URL.
- **Оптимизация:** Работа с поисковым вводом (debounce) и отсутствие лишних ререндеров.
- **Качество кода:** Чистота, читаемость.
